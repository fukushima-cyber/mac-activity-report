# ログ未着の検知と通知

## 保存先

- 生ログのJSON本文: Cloudflare R2 `mac-activity-logs`。
- 社員・組織・受信日時・集計・レポート: Cloudflare D1 `mac-activity-dashboard-db`。
- 収集処理の動作確認: D1 `employee_log_health`。
- 通知条件・通知済み状態・実行ロック: D1 `log_monitor`。

Notionはレポートと議事録の連携先で、生ログの主保存先ではありません。

## 判定

初期状態は無効です。管理画面の「設定 → ログ未着の通知」から有効化します。初期値は平日9〜18時（JST）、猶予120分。勤務開始・有効化・社員登録から猶予を置き、休業日、監視OFF、アップロードトークン未発行、明示除外の社員は通知しません。祝日は自動取得せず会社の休業日に登録します。個別休暇・変則勤務は除外設定で運用し、再開時に解除します。

- 本日未着: 本日（JST）のログがまだありません。過去ログの再送を本日の受信と誤認しません。
- 受信・動作確認が途絶: 本日のログはあるものの、ログ更新も動作確認信号も猶予時間以上ありません。
- 収集・送信エラー: 最新の動作確認信号が処理失敗を報告しています。

社員PCは30分ごとの書き出し処理後に、成功・失敗だけの信号を送ります。内容が変わらずログ送信を省略した場合も信号を送るので、正常な送信省略を停止と誤認しにくくなります。信号には作業内容を含めず、所属は社員専用トークンから判定します。旧エージェントはこの信号を持たないため、通知有効化前に更新してください。

これは受信と書き出し処理の確認であり、勤務態度や業務成果の判定ではありません。PC停止・休暇・権限・ネットワーク等の原因は管理者が確認します。ActivityWatchの各watcherが実際に記録し続けていることや、取得データの完全性までは証明しません。

## 通知

会社専用のSlack Incoming Webhookを保存します。URLは管理画面から再表示せず、公開設定APIにも含めません。Slackへの送信内容は要確認社員名と状態のみで、ウィンドウタイトルや生ログは送信しません。未設定なら外部通知はせず、管理画面の状態表示のみです。

状態が変わった時だけ通知し、同じ状態が続く間の定期再通知は行いません。要確認がなくなった時は解消通知を1回送ります。除外・設定変更による解消も含むため、全ログが復旧したとは断定しません。状態確認と送信は会社単位のD1リースで重複実行を抑え、送信成功後だけ通知済みにします。通知先が受信した直後に通信が切れた場合など、厳密なexactly-once送信は保証できません。

## 自動実行

監視はLLMを使いません。管理者用取り込みトークンで `POST /api/log-monitor/check` を10分おきに実行します。Cloudflareの新規Cron Triggerは勝手に追加しません。

```bash
node --env-file=/absolute/path/report/.env /absolute/path/report/check-log-monitor.mjs
```

このコマンドを常時起動するVPSのcron等へ登録します。例:

```cron
*/10 * * * * /absolute/path/node --env-file=/absolute/path/report/.env /absolute/path/report/check-log-monitor.mjs
```

company-ops-starterではreports利用時の`npm start`が分析と別のループで10分おきに実行します。より確実に分離する場合は`npm run monitor -- --instance <会社ID>`を独立したサービスとして起動します。こちらはNotion・LLMの接続診断を要求しません。二重実行時もサーバーのリースと通知済み状態で送信を抑制します。

監視サービス自体やD1が停止すると、この仕組みから通知できません。画面には最終自動確認を表示し、30分以上確認できなければ警告します。画面を開かなくても監視停止に気づくためには、サービスの死活監視を別の監視基盤へ接続してください。

## 反映順序と検証

1. D1マイグレーション `0009_log_monitor.sql`（先行の`0008`も）を適用。
2. ダッシュボードをビルド・デプロイ。
3. 社員PCの収集エージェントを更新。
4. 自動チェックを常時稼働環境へ登録。
5. 対象曜日・時間・休業日・通知先を確認して有効化。

本番反映・実Webhook登録・実通知は今回の実装テストには含めません。ローカルSQLiteと模擬Slackで未着・重複抑制・送信失敗再試行・解消・組織分離を検証し、ブラウザでは模擬データで設定保存と表示を確認しています。
