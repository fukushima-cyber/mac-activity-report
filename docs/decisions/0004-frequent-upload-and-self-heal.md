# 0004: 社員PCからは起動中30分おきに過去3日分を送り、サーバーは差分だけ作り直す

日付: 2026-09-07

## 背景

毎日23:50固定の1回送信では、その時刻にPCを閉じている人のデータが取れない。人によって稼働時間がバラバラで、
「正午前に動いたら前日分」という追いつきロジックも、午前だけ働いて翌日開かないと1日分が永久に消える穴があった。
さらにActivityWatchは再起動後に自動で立ち上がらず(ログイン項目に無い)、止まると全ての送信が空振りしていた。

## 決定

- 社員PC: launchd `StartInterval`(Mac) / タスクスケジューラの30分繰り返し(Windows)で、起動中は30分おきに
  **今日＋過去2日分**を送る。前回送信から中身が変わっていない日は送らない(ローカルにSHA-256を残して比較)。
  同じ日付はサーバー側で上書きされるので、何度送っても壊れない。
- 社員PC: ActivityWatchをログイン項目/スタートアップに登録し、送信スクリプトも「応答が無ければ起動して最大60秒待つ」。
- サーバー(VPS): 9:00と13:00の2回、`GET /api/logs/pending` で「アップロードがレポートより新しい社員・日」だけを
  過去3日分から拾って作り直す。変更が無い人にはAIを回さないので費用は増えない。引数で日付を渡した時は従来どおり全員分。

## 取りこぼしが残る条件(仕様として受け入れる)

- ActivityWatchが止まっていた時間帯は記録自体が無い(自己修復で再開はするが、その間は取り戻せない)。
- 3日以上PCを開かなかった日の分は送られない。
- アクセシビリティ許可とRosettaの確認はAppleの仕様上、本人のクリックが必要。
- レポート生成中に同じ人の新しいアップロードが届いた場合、その差分(最大30分)は次回まで反映されない。
