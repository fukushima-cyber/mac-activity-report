# 0002: ダッシュボードの認証を自前実装にした理由

## 状況

社員管理ダッシュボード(Cloudflare Workers)にマネージャー複数人がログインする必要がある。dev-brainの既定は「認証は自前実装しない、better-authを使う」。

## 決定

Web標準のPBKDF2(Web Crypto API)によるパスワードハッシュ＋ランダムセッションIDのCookie、という最小構成を自前実装した。

## 理由

- 対象ユーザーは社長が個別に招待する少人数のマネージャーのみ。一般公開のサインアップは無い
- better-authのD1アダプタ導入・設定の分だけ複雑性が増える一方、得られるものが少ない(パスワードリセットメール等は今回不要)
- 実装はPBKDF2(反復10万回)+定数時間ではない比較(タイミング攻撃のリスクはあるが、少人数の社内ツールでは許容範囲と判断)

## 今後better-authへ移行すべきサイン

- ログイン対象が社外の人物に広がる
- パスワードリセット・メール認証・SSOが必要になる
- マネージャーが10人を超える規模になる
